1. SYSTEM OVERVIEW
================================================================================

The AI-Powered Insider Threat Detection System (ThreatSense AI) is a full-stack
web-based prototype that classifies employee behavioural activity records as
either Malicious or Normal using a trained Random Forest machine learning model.
It also produces an explainability report for every prediction that is
understandable by both security analysts and non-technical managers.

Architecture Summary
---------------------
The system is built on a four-tier architecture:

  Tier 1 – Client (Browser):
    React 18 Single Page Application (SPA) pre-built and served as static files.
    Provides a manual entry form, CSV file upload, sample profile cards, and
    result display pages.

  Tier 2 – Application (Flask REST API):
    Python 3 Flask 3 server (app.py) running on port 5000. Hosts the REST API
    and serves the React build. Handles prediction requests, batch CSV
    processing, and explainability generation.

  Tier 3 – ML (scikit-learn):
    A trained RandomForestClassifier and a fitted ColumnTransformer preprocessor
    loaded from serialised pickle files at application startup. Inference is
    performed entirely in-process — no separate ML server is required.

  Tier 4 – Storage (File System):
    Serialised model artefacts (rf_model.pkl, preprocessor.pkl), JSON
    configuration files (thresholds.json, feature_names.json, model_config.json),
    the dataset CSV, and cached batch results (malicious_results.json).

Offline Training:
    A separate script (train_model.py) is run once before the application starts
    to train the model on the Kaggle dataset and write all artefacts to the
    prototype/models/ directory.

Key capabilities:
  - Single record classification via manual web form
  - Batch classification via CSV file upload (up to 100 MB)
  - Pre-defined sample employee profile demonstration
  - Per-prediction risk indicator breakdown (HIGH / MEDIUM / LOW)
  - Plain-English manager explanation for every prediction
  - Global feature importance ranking from the trained model
  - Demo mode when model files are absent (heuristic engine)

3. INSTALLATION INSTRUCTIONS

Step 1 – Clone the Repository
-------------------------------
  git clone <repository-url>
  cd COS720-Threat-Detection/prototype

    python -m venv venv

    python3 -m venv venv
    source venv/bin/activate

  pip install -r requirements.txt

  Download insider_threat_clean_dataset.csv from Kaggle (URL in Section 2)

    prototype/data/insider_threat_clean_dataset.csv

  not included in the repository because of its size and Kaggle licensing.

    python train_model.py

    rf_model.pkl, preprocessor.pkl, thresholds.json, feature_names.json,
    confusion_matrix.png, feature_importance.png, metrics_report.txt

    Accuracy : 95.84%
    Precision: 58.86%
    Recall   : 75.72%
    F1-Score : 66.23%
    Model saved to .../prototype/models/rf_model.pkl

  Training time: approximately 2–5 minutes on a standard laptop CPU.

  After training, confirm the following files exist:
    prototype/models/rf_model.pkl
    prototype/models/preprocessor.pkl
    prototype/models/thresholds.json
    prototype/models/feature_names.json

4. DEPLOYMENT AND EXECUTION INSTRUCTIONS
================================================================================

Starting the Application
--------------------------
  From the prototype/backend/ directory with the virtual environment activated:

    python app.py

  Expected output:
    INFO  [main] Model loaded successfully.
    INFO  [werkzeug]  * Running on http://127.0.0.1:5000

  Open a web browser and navigate to:
    http://localhost:5000

  The Flask server serves both the REST API (/api/*) and the pre-built React
  frontend (all other paths). No separate web server is required.

Running Without a Trained Model (Demo Mode)
--------------------------------------------
  If rf_model.pkl is not present, the application starts in demo mode.
  In demo mode, predictions are generated by a heuristic scoring engine
  (in app.py: predict_demo()) that applies rule-based thresholds to the
  input features. Classification accuracy is lower than the trained model
  but the application remains fully functional for demonstration purposes.
  The frontend will display a "DEMO MODE" banner in the navigation bar.

Running the Frontend in Development Mode  (optional)
------------------------------------------------------
  If modifying the React frontend source code, start the development server
  (requires Node.js 18+):

  Terminal 1 – Start the Flask API:
    cd prototype/backend
    python app.py

  Terminal 2 – Start the React dev server (proxies /api to port 5000):
    cd prototype/frontend
    npm install          (first time only)
    npm start            (opens http://localhost:3000)

  The setupProxy.js file in prototype/frontend/src/ configures the dev-server
  proxy to forward all /api requests to http://localhost:5000.

Rebuilding the Frontend Production Build  (optional)
------------------------------------------------------
  cd prototype/frontend
  npm run build
  (Output written to prototype/frontend/build/ — commit this directory)

Stopping the Server
---------------------
  Press Ctrl + C in the terminal running app.py.

──────────────────────────────────────────────────────────────────────────────
app.py  –  Flask REST API Server
──────────────────────────────────────────────────────────────────────────────
Entry point for the application. Loads the trained model and preprocessor at
startup, registers all API route handlers, and serves the React static build.

Configuration:
  BUILD_DIR             Path to prototype/frontend/build/
  MODELS_DIR            Path to prototype/models/
  MAX_CONTENT_LENGTH    100 MB (upload limit)

Key functions:
  load_model()
    Called at application startup. Loads rf_model.pkl, preprocessor.pkl,
    thresholds.json, and feature_names.json using joblib. Sets model_loaded=True
    on success. Falls back to demo mode if files are not found.

  predict_record(record: dict) → dict
    Transforms a single dict of feature values using transform_single_record(),
    runs model.predict() and model.predict_proba(), and returns the prediction
    integer, probability float, and a call to explain_prediction().

  predict_batch_chunked(df: DataFrame, chunk_size: int) → tuple
    Processes a DataFrame of multiple records in chunks to avoid memory issues
    on large uploads. Returns (predictions array, probabilities array).

  predict_demo(record: dict) → dict
    Heuristic classification used when model files are absent. Applies simple
    threshold rules to key features (total_files_burned, burned_from_other,
    num_printed_pages_off_hours, entry_during_weekend) to produce a demo
    prediction and probability.

API Endpoints:
  GET  /api/health          Returns model status and version information.
  GET  /api/features        Returns feature metadata (labels, types, defaults).
  GET  /api/samples         Returns all sample profile metadata (no prediction).
  GET  /api/sample/<id>     Runs a prediction on sample profile with given id.
  POST /api/predict         Accepts JSON body (single record) or multipart/form-
                            data with a CSV file. Returns prediction result(s).
  GET  /api/malicious       Returns cached batch results from malicious_results.json.
  POST /api/explain         Accepts a single record JSON and returns explainability
                            output without rerunning the full prediction pipeline.
  GET  /*                   Catch-all: serves the React index.html for SPA routing.

──────────────────────────────────────────────────────────────────────────────
preprocess.py  –  Data Loading and Preprocessing Module
──────────────────────────────────────────────────────────────────────────────
Module-level constants define the feature lists and human-readable labels.

NUMERIC_FEATURES (list):
  10 numeric features: employee_seniority_years, total_files_burned,
  burned_from_other, num_printed_pages_off_hours, total_printed_pages,
  num_entries, late_exit_flag, entry_during_weekend, trip_day_number,
  hostility_country_level.

CATEGORICAL_FEATURES (list):
  3 categorical features: employee_department, employee_classification,
  is_contractor.

TARGET_COLUMN: "is_malicious"

FEATURE_LABELS (dict):  Maps internal column names to display labels.

Key functions:
  load_dataset(filepath) → DataFrame
    Reads the CSV, validates that required columns are present, fills missing
    numeric values with the column median, and fills missing categorical values
    with the column mode.

  build_preprocessor(numeric, categorical) → ColumnTransformer
    Constructs a scikit-learn ColumnTransformer with a StandardScaler pipeline
    for numeric features and an OneHotEncoder (handle_unknown='ignore') pipeline
    for categorical features.

  prepare_features(df) → (X, y)
    Separates the DataFrame into feature matrix X and target vector y.

  compute_thresholds(X, y, features) → dict
    For each numeric feature, computes the 75th percentile of normal (y=0)
    records and the 25th percentile of malicious (y=1) records. These
    thresholds are used by the explainability engine to classify feature
    values as HIGH / MEDIUM / LOW risk.

  save_preprocessor(preprocessor, path) → void
    Serialises the fitted ColumnTransformer to a pickle file using joblib.

  load_preprocessor(path) → ColumnTransformer
    Deserialises the ColumnTransformer from the pickle file.

  transform_single_record(record, preprocessor, numeric, categorical) → ndarray
    Converts a dict of feature name→value pairs into a 2D ndarray suitable
    for model.predict() / model.predict_proba(). Handles type coercion and
    column alignment internally.

──────────────────────────────────────────────────────────────────────────────
train_model.py  –  Model Training Script
──────────────────────────────────────────────────────────────────────────────
Standalone script executed once to produce all trained model artefacts.

RF_PARAMS (dict):
  n_estimators=200, max_depth=None, min_samples_split=5, min_samples_leaf=2,
  class_weight='balanced', random_state=42, n_jobs=-1.

train_and_evaluate():
  1. Loads the dataset via load_dataset().
  2. Splits into 80% train / 20% test with stratified sampling.
  3. Builds and fits the ColumnTransformer preprocessor.
  4. Trains the RandomForestClassifier.
  5. Computes accuracy, precision, recall, F1-score, and confusion matrix.
  6. Computes per-feature thresholds via compute_thresholds().
  7. Saves rf_model.pkl, preprocessor.pkl, thresholds.json, feature_names.json,
     model_config.json to prototype/models/.
  8. Generates confusion_matrix.png and feature_importance.png.
  9. Writes metrics_report.txt with the full classification report.

──────────────────────────────────────────────────────────────────────────────
explainability.py  –  Risk Indicator and Explanation Engine
──────────────────────────────────────────────────────────────────────────────
Provides all explainability functionality. The Explainer class is instantiated
at application startup with the loaded thresholds and feature importances.

RISK_MULTIPLIERS (dict):
  HIGH: > 2.0× the normal 75th percentile threshold.
  MEDIUM: > 1.2× the threshold.
  LOW: > 0.8× the threshold.

FEATURE_EXPLANATIONS (dict):
  Plain-English explanations for each feature at each risk level. Written
  to be understandable by a non-technical manager without security background.

Explainer class:
  __init__(thresholds, feature_importances, numeric_features, categorical_features)
    Stores thresholds and importance weights for use in risk calculations.

  get_risk_level(feature, value) → str
    Returns "HIGH", "MEDIUM", "LOW", or "NORMAL" for a given feature value
    based on the RISK_MULTIPLIERS applied to the normal_75th threshold.

  get_risk_indicators(instance) → list[dict]
    Iterates over all numeric and categorical features in the instance dict,
    computes the risk level for each, and returns a sorted list of indicator
    dicts containing feature name, display label, value, risk level, colour,
    and plain-English explanation. Only features above NORMAL are included.

  generate_manager_explanation(prediction, probability, indicators) → str
    Produces a multi-sentence plain-English paragraph summarising the
    classification, confidence level, and the top three risk drivers.

  get_global_feature_importance(top_n) → list[dict]
    Returns the top_n features sorted by MDI importance score descending,
    formatted as a list of {feature, label, importance} dicts.

  explain_prediction(instance, prediction, probability) → dict
    Orchestrates the full explainability pipeline: calls get_risk_indicators(),
    generate_manager_explanation(), and get_global_feature_importance(), and
    packages the results into a single response dict.

──────────────────────────────────────────────────────────────────────────────
generate_sample_data.py  –  Sample Profiles and Synthetic Data
──────────────────────────────────────────────────────────────────────────────
SAMPLE_PROFILES (list):
  Five pre-defined employee profiles for demonstration:
    1. Normal employee – all features within normal thresholds.
    2. Borderline case – slightly elevated printing, recent travel, weekend entry.
    3. Clear malicious – very high file burning, off-hours printing, high clearance.
    4. False positive risk – senior executive with authorised heavy activity.
    5. IT contractor – weekend access, files burned from unusual locations.

generate_synthetic_dataset(n_normal, n_malicious) → DataFrame

  real dataset proportions. Output saved to prototype/data/sample_demo_data.csv.

6. DESCRIPTION OF TRAINED MODEL FILES
================================================================================

All trained model artefacts are stored in prototype/models/. They are produced
by running python train_model.py and must be present before starting app.py
(except when running in demo mode).

rf_model.pkl
  Type:    Serialised scikit-learn RandomForestClassifier (joblib pickle)
  Purpose: The trained classification model. Loaded at startup and used for
           all predictions via model.predict() and model.predict_proba().
  Config:  n_estimators=200, class_weight='balanced', random_state=42.
  Size:    Approximately 150–300 MB depending on tree depth.

preprocessor.pkl
  Type:    Serialised scikit-learn ColumnTransformer (joblib pickle)
  Purpose: Fitted data transformer. Applied to every input record before it
           is passed to the model. Contains a fitted StandardScaler for the
           10 numeric features and a fitted OneHotEncoder for the 3 categorical
           features.
  Size:    < 1 MB.

thresholds.json
  Type:    JSON object
  Purpose: Per-feature risk thresholds used by the Explainer to classify
           feature values as HIGH, MEDIUM, LOW, or NORMAL.
  Schema:
  {
    "<feature_name>": {
      "normal_75th": <float>,     (75th percentile of normal records)
      "malicious_25th": <float>   (25th percentile of malicious records)
    },
    ...
  }

feature_names.json
  Type:    JSON array of strings
  Purpose: Ordered list of feature names after preprocessing (including one-hot
           encoded column names). Used to align model input arrays with the
           correct feature order.
  Schema:  ["employee_seniority_years", "total_files_burned", ...,
            "employee_department_Engineering", ...]

model_config.json
  Type:    JSON object
  Purpose: Metadata about the trained model: hyperparameters, training date,
           dataset statistics, and performance metrics. Used by the /api/health
           endpoint to report system status.
  Schema:
  {
    "model_type": "RandomForestClassifier",
    "n_estimators": 200,
    "class_weight": "balanced",
    "accuracy": 0.9584,
    "precision": 0.5886,
    "recall": 0.7572,
    "f1_score": 0.6623,
    "trained_on": "<ISO date>",
    "n_train": 94891,
    "n_test": 23723
  }

malicious_results.json  (in prototype/data/)
  Type:    JSON array
  Purpose: Cached results from the most recent batch CSV prediction. Populated
           when a CSV is uploaded and a prediction is run on all records.
           Read by GET /api/malicious to avoid reprocessing on page refresh.
  Schema:  Array of prediction result objects, same format as POST /api/predict
           response for individual records.

confusion_matrix.png  (in prototype/models/ — generated by train_model.py)
  A heatmap visualisation of the confusion matrix on the test set. Shows
  True Negatives, False Positives, False Negatives, and True Positives.

feature_importance.png  (in prototype/models/ — generated by train_model.py)
  A horizontal bar chart of the top 15 features ranked by Mean Decrease in
  Impurity (MDI) importance score from the trained Random Forest.

metrics_report.txt  (in prototype/models/ — generated by train_model.py)
  Full scikit-learn classification_report output including per-class precision,
  recall, F1-score, and support for both Normal and Malicious classes.

8. TROUBLESHOOTING NOTES
================================================================================

Issue: "Model files not found" warning on startup / application runs in DEMO MODE
Fix:   Run python train_model.py from the prototype/backend/ directory with the
       virtual environment activated. Ensure the Kaggle dataset CSV is present
       at prototype/data/insider_threat_clean_dataset.csv before training.

Issue: FileNotFoundError: insider_threat_clean_dataset.csv
Fix:   Download the dataset from Kaggle (see Section 2 for the URL) and place
       it in prototype/data/. The file must be named exactly as above.

Issue: ModuleNotFoundError when starting app.py or train_model.py
Fix:   Ensure the virtual environment is activated (venv\Scripts\activate on
       Windows) and all dependencies are installed (pip install -r requirements.txt).

Issue: Port 5000 already in use (OSError: [Errno 98] Address already in use)
Fix:   Another process is using port 5000. Either stop the conflicting process
       or change the port in app.py: app.run(port=5001, ...) and access the
       app at http://localhost:5001.
       On macOS, AirPlay Receiver uses port 5000 by default; disable it in
       System Preferences > Sharing > AirPlay Receiver.

Issue: CSV upload returns 413 Request Entity Too Large
Fix:   The uploaded CSV exceeds 100 MB. Split the file into smaller chunks.
       The limit is set by MAX_CONTENT_LENGTH in app.py and can be increased
       if needed: app.config['MAX_CONTENT_LENGTH'] = 200 * 1024 * 1024

Issue: Predictions are returning "DEMO" classification on all records
Fix:   The application is running in demo mode. The heuristic engine is active.
       Run train_model.py to generate the real model files and restart app.py.

Issue: React frontend shows a blank page at http://localhost:5000
Fix:   The frontend/build/ directory is empty or missing. Either run
       "npm run build" in prototype/frontend/ and copy the output, or access
       the React development server directly at http://localhost:3000 (requires
       npm start to be running alongside app.py).

Issue: Training completes but metrics_report.txt shows very low recall (<50%)
Fix:   Verify that the correct Kaggle dataset file has been placed in
       prototype/data/. A truncated or incorrect CSV will produce degraded
       metrics. The expected recall on the full dataset is approximately 75.7%.

Issue: CORS errors in the browser console when calling /api/* endpoints
Fix:   This should not occur when using the production build served from port
       5000. If running the React dev server on port 3000, ensure setupProxy.js
       is present in prototype/frontend/src/ (it proxies all /api requests to
       http://localhost:5000).

Issue: train_model.py runs very slowly (> 10 minutes)
Fix:   Ensure n_jobs=-1 is set in RF_PARAMS to use all available CPU cores.
       On machines with limited RAM, reduce n_estimators to 100 in RF_PARAMS
       (slight accuracy decrease but significantly faster training).
